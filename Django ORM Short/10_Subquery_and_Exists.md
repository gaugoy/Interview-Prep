<a name="q1"></a>
## Q1. (Easy) What is the purpose of Subquery in Django ORM?
**Answer:** `Subquery` embeds one queryset inside another as an SQL subquery — to annotate each row with a value from a related table (latest order date, last status) or to filter by another query, all in **one** SQL statement instead of a query per row.

```python
latest = Order.objects.filter(customer=OuterRef("pk")).order_by("-created_at")
Customer.objects.annotate(last_status=Subquery(latest.values("status")[:1]))
```

---

<a name="q2"></a>
## Q2. (Easy) How does OuterRef work and how is it evaluated inside a Subquery?
**Answer:** `OuterRef("pk")` is a placeholder meaning "the column from the outer query's current row". It's resolved when the subquery is attached to the outer query, producing a **correlated** subquery: `WHERE order.customer_id = customer.id`. It only works inside `Subquery`/`Exists`.

---

<a name="q3"></a>
## Q3. (Medium) What is the Exists class and when should you use it over filter(related__isnull=False)?
**Answer:** `Exists(qs)` → `EXISTS (SELECT 1 ... )`, true if any matching row exists. `filter(orders__isnull=False)` JOINs the relation and returns a parent once **per matching child** (duplicates → needs `distinct()`). `Exists` is a semi-join: no duplicates, stops at the first match, and easily adds conditions.

```python
Customer.objects.filter(Exists(Order.objects.filter(customer=OuterRef("pk"), status="paid")))
```

---

<a name="q4"></a>
## Q4. (Medium) How does Django translate a Subquery into an SQL subquery?
**Answer:** The inner queryset is compiled separately and inserted in parentheses where it's used (SELECT list, WHERE, ORDER BY); `OuterRef`s become references to the outer table's alias; params are merged in order.

```sql
SELECT customer.*, (SELECT U0.status FROM shop_order U0
                    WHERE U0.customer_id = customer.id ORDER BY U0.created_at DESC LIMIT 1) AS last_status
FROM shop_customer customer;
```

---

<a name="q5"></a>
## Q5. (Easy) What are the restrictions of using Subquery (e.g., returning a single column)?
**Answer:** Used as an annotation/value, the subquery must return **one column** (`.values("field")`) and at most **one row** (`[:1]`). In `__in` filters it may return many rows but still one column. It must use the same database as the outer query.

---

<a name="q6"></a>
## Q6. (Medium) How do you perform updates using Subquery in Django ORM?
**Answer:** Use a `Subquery` as the value in `update()` — one statement updates all rows from related data.

```python
total = OrderItem.objects.filter(order=OuterRef("pk")).values("order") \
                         .annotate(s=Sum("amount")).values("s")
Order.objects.update(total=Subquery(total))
```
(MySQL can't select from the table being updated in a subquery.)

---

<a name="q7"></a>
## Q7. (Medium) What is the performance difference between a SQL subquery and a SQL JOIN?
**Answer:** Often the planner turns them into the same plan. Rules of thumb: JOIN is good when you need columns from both tables; `EXISTS`/`IN` subqueries are better for "has related rows" (no duplicates); a correlated subquery in SELECT may run once per outer row — fine with an index and paginated results, slow over millions of rows. Check with `EXPLAIN`.

<a name="q8"></a>
## Q8. (Hard) How do you reference multiple OuterRef objects in nested subqueries?
**Answer:** Each `OuterRef` refers to the query **one level up**. To reach two levels up, nest it: `OuterRef(OuterRef("pk"))`.

```python
reviews = Review.objects.filter(book=OuterRef("pk"), author=OuterRef(OuterRef("pk")))
books = Book.objects.filter(author=OuterRef("pk")).filter(Exists(reviews))
Author.objects.annotate(has_self_reviewed=Exists(books))
```

<a name="q9"></a>
## Q9. (Easy) How do you filter a Subquery based on conditions from the outer query?
**Answer:** Use `OuterRef` for any outer column in the subquery's filter, alongside normal conditions.

```python
cheaper = Product.objects.filter(category=OuterRef("category"), price__lt=OuterRef("price"))
Product.objects.annotate(cheaper_exists=Exists(cheaper))
```

<a name="q10"></a>
## Q10. (Easy) What happens when a Subquery returns multiple rows and how do you prevent errors?
**Answer:** The DB raises an error like "more than one row returned by a subquery used as an expression". Prevent it by ordering and slicing to one row (`.order_by("-created_at").values("x")[:1]`), or by aggregating inside the subquery so it returns a single value.

---

<a name="q11"></a>
## Q11. (Easy) How do you use Subquery with annotation to get the latest record of a relationship?
**Answer:**

```python
latest = Payment.objects.filter(invoice=OuterRef("pk")).order_by("-paid_at")
Invoice.objects.annotate(
    last_paid_at=Subquery(latest.values("paid_at")[:1]),
    last_amount=Subquery(latest.values("amount")[:1]))
```
Index `(invoice_id, paid_at)` so each lookup is cheap. For the whole latest object, prefetch with a sliced `Prefetch` instead.

---

<a name="q12"></a>
## Q12. (Easy) How do you use Exists to conditionally annotate a queryset with a boolean?
**Answer:**

```python
Customer.objects.annotate(
    has_open_ticket=Exists(Ticket.objects.filter(customer=OuterRef("pk"), status="open")))
```
You can then filter on it (`.filter(has_open_ticket=True)`) or use `~Exists(...)` for "has none".

---

<a name="q13"></a>
## Q13. (Medium) What is the SQL generated by Exists compared to normal count filter?
**Answer:** `Exists` → `EXISTS (SELECT 1 ... LIMIT 1)` — stops at the first match. A count filter (`annotate(n=Count("orders")).filter(n__gt=0)`) → JOIN + `GROUP BY` + `HAVING COUNT(...) > 0` — counts every related row for every parent first. For yes/no checks `Exists` is much cheaper.

---

<a name="q14"></a>
## Q14. (Medium) How do you combine Subquery with F expressions?
**Answer:** Use the subquery value in arithmetic or comparisons with F like any expression.

```python
avg_price = Product.objects.filter(category=OuterRef("category")).values("category") \
                           .annotate(a=Avg("price")).values("a")
Product.objects.annotate(cat_avg=Subquery(avg_price)).filter(price__gt=F("cat_avg"))
```

---

<a name="q15"></a>
## Q15. (Medium) How do you perform math operations inside a Subquery?
**Answer:** Aggregate inside the subquery by grouping on the correlated key, then return the value (often with `Coalesce` for no rows).

```python
spent = Order.objects.filter(customer=OuterRef("pk")).values("customer") \
                     .annotate(total=Sum(F("qty") * F("price"))).values("total")
Customer.objects.annotate(spent=Coalesce(Subquery(spent), Value(0), output_field=DecimalField()))
```

---

<a name="q16"></a>
## Q16. (Medium) What are the limitations of MySQL/MariaDB backend regarding subqueries?
**Answer:** MySQL doesn't allow `LIMIT` inside `IN (subquery)`, can't select from the same table you're updating/deleting in a subquery, and older versions optimized correlated subqueries poorly. Django works around some cases; otherwise rewrite as a JOIN or two queries.

---

<a name="q17"></a>
## Q17. (Medium) How do you debug slow subqueries using EXPLAIN in Django?
**Answer:** Run `qs.explain(analyze=True)` (PostgreSQL) and look for a SubPlan executed once per outer row with a high loop count, or seq scans inside it. Usually fix by indexing the correlated columns (`fk`, order column), limiting outer rows, or rewriting as a JOIN/aggregate.

---

<a name="q18"></a>
## Q18. (Medium) Can you use prefetch_related with a Subquery?
**Answer:** Yes. The `Prefetch` queryset can contain `Subquery`/`Exists` annotations or filters, and you can add subquery annotations to the main queryset that also prefetches.

```python
Prefetch("orders", queryset=Order.objects.annotate(
    has_refund=Exists(Refund.objects.filter(order=OuterRef("pk")))))
```

<a name="q19"></a>
## Q19. (Medium) How does Django 5.0 handle subqueries in asynchronous queries?
**Answer:** Same as sync — `Subquery`/`Exists` are just part of the SQL. Evaluate with async methods: `await qs.afirst()`, `async for row in qs`. Building the queryset is lazy and doesn't touch the DB.

<a name="q20"></a>
## Q20. (Hard) How do you write nested subqueries to retrieve hierarchical data?
**Answer:** For a fixed number of levels, nest subqueries with `OuterRef(OuterRef(...))` (e.g. grandparent info). For arbitrary depth, Django subqueries aren't enough — use a recursive CTE (raw SQL / `django-cte`) or a tree structure (MPTT, materialized path).

---

<a name="q21"></a>
## Q21. (Easy) How do you handle NULL values returned by a Subquery?
**Answer:** A subquery that finds no row returns NULL. Wrap it in `Coalesce` with a default of the same type.

```python
Customer.objects.annotate(
    last_total=Coalesce(Subquery(latest.values("total")[:1]), Value(0), output_field=DecimalField()))
```

<a name="q22"></a>
## Q22. (Medium) What is the SQL difference between IN, EXISTS, and JOIN in Django ORM?
**Answer:**
- `filter(id__in=qs.values("x"))` → `WHERE id IN (SELECT x ...)`.
- `filter(Exists(...))` → correlated `WHERE EXISTS (SELECT 1 ...)`.
- `filter(rel__field=...)` → `INNER JOIN` + WHERE (may duplicate parents).
IN and EXISTS are semi-joins without duplicates. **Gotcha:** `NOT IN` returns nothing if the subquery has a NULL — prefer `~Exists`.

<a name="q23"></a>
## Q23. (Medium) How do you build a dynamic subquery based on user search parameters?
**Answer:** Build the inner queryset step by step from validated params, then use it in `Exists`/`__in`.

```python
orders = Order.objects.filter(customer=OuterRef("pk"))
if status := params.get("status"):
    orders = orders.filter(status=status)
if since := params.get("since"):
    orders = orders.filter(created_at__gte=since)
Customer.objects.filter(Exists(orders))
```

<a name="q24"></a>
## Q24. (Easy) How do you map a subquery to a non-primary key field of the outer query?
**Answer:** Point `OuterRef` at any outer field, not just `pk`.

```python
rates = ExchangeRate.objects.filter(currency=OuterRef("currency_code")).order_by("-date")
Invoice.objects.annotate(rate=Subquery(rates.values("rate")[:1]))
```
Index the inner column (`currency`, `date`).

---

<a name="q25"></a>
## Q25. (Medium) Explain the performance impact of correlated subqueries vs. non-correlated subqueries.
**Answer:** A **non-correlated** subquery (no `OuterRef`) runs once and is reused. A **correlated** subquery depends on each outer row, so in the worst case it runs once per row — fine with a good index and few outer rows, slow on large result sets. The planner can sometimes turn it into a join (e.g. EXISTS → semi-join).

---

<a name="q26"></a>
## Q26. (Hard) How do you write a subquery that evaluates array aggregates?
**Answer:** On PostgreSQL, `ArraySubquery` returns all values of a subquery as an array (one per outer row).

```python
from django.contrib.postgres.expressions import ArraySubquery
tags = Tag.objects.filter(article=OuterRef("pk")).values("name")
Article.objects.annotate(tag_names=ArraySubquery(tags))
```

---

<a name="q27"></a>
## Q27. (Hard) Explain the OuterRef limitation inside double nested subqueries.
**Answer:** `OuterRef("x")` only reaches the **immediate** outer query. Inside a sub-subquery, `OuterRef("pk")` refers to the middle query, not the top one — you must write `OuterRef(OuterRef("pk"))` to reach the top level. Getting this wrong silently correlates to the wrong table.

---

<a name="q28"></a>
## Q28. (Hard) How do you write a subquery that returns a JSON list of related objects?
**Answer:** PostgreSQL: combine `JSONObject` with `ArraySubquery` (or `JSONBAgg`).

```python
from django.db.models.functions import JSONObject
items = OrderItem.objects.filter(order=OuterRef("pk")).values(
    data=JSONObject(sku="product__sku", qty="quantity"))
Order.objects.annotate(items=ArraySubquery(items))
```
Good for read-only API payloads in one query.

---

<a name="q29"></a>
## Q29. (Hard) What is the difference between EXISTS and IN execution plans in PostgreSQL?
**Answer:** For positive checks PostgreSQL usually plans both as the same semi-join (hash/merge/nested loop). The difference is with negation: `NOT EXISTS` becomes an efficient anti-join, while `NOT IN (subquery)` is often slower and returns **no rows** if the subquery contains a NULL. Prefer `~Exists` for "not in".

---

<a name="q30"></a>
## Q30. (Hard) How does the compiler evaluate subquery parameter ordering?
**Answer:** Each part of the SQL (SELECT expressions, FROM/JOINs, WHERE, HAVING, ORDER BY) is compiled into SQL + its own param list, and the lists are concatenated in the same order the parts appear in the final SQL. Subqueries contribute their params at the position where they're embedded, so placeholders and values always line up.

---

<a name="q31"></a>
## Q31. (Hard) How do you execute custom SQL inside a Subquery wrapper?
**Answer:** `Subquery` needs a queryset. For raw SQL use `RawSQL` as an expression (with params), or a custom `Func`.

```python
from django.db.models.expressions import RawSQL
Customer.objects.annotate(score=RawSQL(
    "SELECT score FROM crm_score s WHERE s.customer_id = shop_customer.id", []))
```
Raw SQL depends on table aliases — fragile; keep it minimal.

---

<a name="q32"></a>
## Q32. (Hard) What is the performance overhead of executing 10 correlated subqueries in a single queryset?
**Answer:** Each correlated subquery may run once per outer row: 10 subqueries × 10,000 rows = up to 100,000 small lookups. Fine for a paginated page with good indexes; slow for exports. Combine values from the same table (one JOIN/LATERAL, or a single aggregate subquery), use prefetch, or pre-compute into a summary table.

---

<a name="q33"></a>
## Q33. (Medium) How do you write a subquery that references models across separate databases?
**Answer:** You can't — a subquery is part of one SQL statement on one database. Run two queries: get the values from database A (`values_list`), then filter database B with `__in` (chunk large lists), or merge results in Python.

---

<a name="q34"></a>
## Q34. (Hard) How do you enforce check constraints that check subquery results?
**Answer:** Databases (PostgreSQL included) don't allow subqueries in `CHECK` constraints. Options: a trigger that runs the query and raises an error, an exclusion constraint for overlap rules (PostgreSQL), or validation in application code inside a transaction with locking.

---

<a name="q35"></a>
## Q35. (Medium) Explain how to write a subquery that fetches a conditional column alias.
**Answer:** Pick which subquery value to return per row with `Case`/`When`.

```python
Product.objects.annotate(display_price=Case(
    When(on_sale=True, then=Subquery(sale_prices.values("price")[:1])),
    default=F("price")))
```
